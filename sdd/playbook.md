# Playbook de landmines — formato ACE-lite

Cada bullet tem ID estável (`LM-nnn`, nunca reusado), contadores `ajudou`/`mordeu`, `conf=` (última
confirmação) e `sup:` (superfícies greppáveis: nome de arquivo, comando, conceito). Regras completas na
skill `sdd-playbook`; formato validado por `sdd/bin/playbook-lint.sh`.

Como usar: a seção `## Sempre` é lida no início de toda sessão. O resto entra por superfície:
`sdd/bin/playbook-lint.sh --grep <termo> sdd/playbook.md` (fase Design e fase Build).
Nunca reescrever em massa, nunca renumerar, nunca apagar: aposentar = mover para `## Tombstones`
como `- [LM-nnn] ☠ data :: motivo`. Uma sessão só PROPÕE candidatos; quem aplica é a fase Release.

## Sempre

- [LM-001] ajudou=5 mordeu=0 · conf=2026-11-10 · sup: `grep -q` `verify-gate` `if (true)` `asserção` :: Um gate que só confere FIAÇÃO (o `grep` acha a chamada, a regra CSS existe) fica verde com `if (true)` — ele prova que o texto está lá, não que o comportamento acontece. **Do instead:** o gate EXECUTA o código com fixtures dos dois lados (caso que passa E caso que falha) e valida-se com um mutante que derruba uma asserção nomeada. · promovido_para: —
- [LM-002] ajudou=5 mordeu=0 · conf=2026-11-10 · sup: `exit 0` `baseline` `sed -n` `grep -c` :: Uma asserção que NÃO AVALIA NADA sai `exit 0`: quoting corrompido faz o `grep` nem rodar, âncora de `sed` casa o bloco errado e a contagem dá zero antes e depois. **Do instead:** toda asserção precisa de baseline VERMELHO — rode-a contra a árvore ANTES da mudança; se já passa, ela não prova a mudança. · promovido_para: —
- [LM-003] ajudou=5 mordeu=0 · conf=2026-11-10 · sup: `git status` `--uncommitted` `review` `untracked` :: Trabalho commitado com arquivos untracked ao lado faz um review de "não commitado" revisar o VAZIO — e um review que passou sobre diff nenhum é pior que review nenhum. **Do instead:** commitar antes de qualquer review externo; conferir que o diff revisado tem os arquivos que você mudou (`git diff --stat` bate com a lista do review). · promovido_para: —
- [LM-004] ajudou=1 mordeu=0 · conf=2026-11-10 · sup: `exit 0` `migration` `db push` `apply_migration` `Migrations aplicadas` :: Migration "aplicada" porque o comando saiu `exit 0` pode não estar no banco: a CLI ligada a outro projeto, `declined` do servidor, SQL sem efeito — e o código vai para produção chamando a coluna que não existe. **Do instead:** prova é ler de volta — `migration list` mostra a versão no remoto e um `select` acha o efeito (ou a ausência esperada); registre em `## Migrations aplicadas` com o log em `evidence/`. · promovido_para: `sdd/bin/report-lint.py`

## Reviews / harness

- [LM-005] ajudou=4 mordeu=1 · conf=2026-11-10 · sup: `heurística` `regressão` `conserto` :: Conserto que estreita uma heurística sobre texto livre abre o caso vizinho: na F14, cada ajuste da regra que adivinhava a célula de veredito criou o defeito seguinte, em 3 ciclos seguidos do avaliador; na F19, a regra que escolhia "a tabela do ledger" regrediu 2 vezes e, depois dela, uma linha sem a barra inicial ainda passava. **Do instead:** na 2ª regressão da mesma regra, pare de ajustar: troque a heurística por uma fonte estruturada e recuse o que não tiver essa fonte; quando a fonte é um arquivo, ele guarda uma coisa só e toda linha com forma de dado é conferida ou acusada, inclusive fora da tabela; dois scripts que leem o mesmo arquivo usam a mesma função, com teste que compara o texto das duas cópias. → ficha: — · promovido_para: —
- [LM-006] ajudou=4 mordeu=0 · conf=2026-11-10 · sup: `verify-gate` `git archive` `self-test` :: Script que só roda dentro de um repositório git passa no teste local e falha no gate, que roda numa cópia sem `.git`; e uma asserção de "bloqueou" que aceita qualquer exit diferente de 0 fica verde quando a ferramenta nem rodou. **Do instead:** rode o self-test novo numa cópia sem `.git` (extraída com `git archive`) antes do gate, e confira o exit exato do que deve reprovar. → ficha: — · promovido_para: —
- [LM-007] ajudou=0 mordeu=0 · conf=2026-11-06 · sup: `git diff --name-only` `--no-renames` `rename` :: `git diff --name-only` mostra só o nome novo de um rename: uma conferência de "só documento mudou" aceita código movido para a pasta de documento, e o commit que a própria ação pede apaga o sinal. **Do instead:** nessa conferência, passar `--no-renames`, com teste do rename sujo e do commitado, nos 2 sentidos. → ficha: — · promovido_para: —
- [LM-008] ajudou=0 mordeu=0 · conf=2026-11-06 · sup: `HTTP 402` `limit_remaining` `/credits` :: O `limit_remaining` de uma chave da OpenRouter é o limite da chave, não o saldo da conta: um revisor caiu com HTTP 402, com "US$ 220 restantes", a queda foi lida como passageira e se repetiu na rodada paga seguinte. **Do instead:** antes de uma rodada paga, ler o saldo em `/api/v1/credits`; revisor que cai pede a mensagem do provedor antes de qualquer conclusão. → ficha: — · promovido_para: —
- [LM-009] ajudou=2 mordeu=0 · conf=2026-11-10 · sup: `git checkout` `mutante` `sabotagem` `não commitado` :: Script de sabotagem que desfaz cada mutante com `git checkout -- <arquivo>` apaga junto o conserto ainda não commitado naquele arquivo (na F15_SLOTS, consertos de `slot.sh` e `test-baseline.sh` sumiram e precisaram ser restaurados de cópias). **Do instead:** commite o conserto antes da sabotagem e faça o script recusar árvore com mudança rastreada (`git status --porcelain --untracked-files=no` não vazio ⇒ sai sem mutar), ou aplique os mutantes numa cópia extraída com `git archive`. → ficha: — · promovido_para: —
- [LM-010] ajudou=2 mordeu=0 · conf=2026-11-10 · sup: `openrouter` `teto` `timeout` `saldo` :: Engine da OpenRouter que passa do teto de tempo do registry é cobrada mesmo sem devolver resposta, e o ledger só mostra `custo $?` (na F15_SLOTS, o 2º revisor estourou 900 s e o saldo caiu de US$ 2,39 para 1,32). **Do instead:** no papel de 2º revisor, use um modelo cujo tempo já foi medido abaixo do teto; anote no ledger o saldo de `/credits` antes e depois da rodada e não repita na rodada seguinte o modelo que estourou. → ficha: — · promovido_para: —
- [LM-011] ajudou=0 mordeu=0 · conf=2026-11-10 · sup: `evals` `texto canônico` `instrução embutida` `cenário comportamental` :: Cenário de comportamento escrito e nunca executado esconde o defeito do texto: na F21, as 3 execuções do pedido de acesso indevido recusaram, mas só 1 usou a frase canônica, e nas 3 do manual com instrução embutida o agente não obedeceu e também não contou ao usuário que a instrução existia. **Do instead:** escreva o critério de aprovado antes de rodar, rode cada negativo 3 vezes em contexto novo, conserte o texto e rode outra série; registre as duas séries. → ficha: — · promovido_para: —
- [LM-012] ajudou=0 mordeu=0 · conf=2026-11-10 · sup: `publish-gate` `sha256` `[0-9]{11,}` `manifest.json` :: Um SHA-256 escrito inteiro num arquivo do pacote tem chance real de trazer 11 dígitos seguidos e é barrado pelo `publish-gate` como número longo (na F21, 1 dos 11 hashes do material de origem). **Do instead:** em texto que vai para o pacote, use o prefixo de 12 caracteres, ou confira o arquivo contra `scripts/publish-gate-patterns.txt` antes do gate; hash inteiro só em constante de teste já conferida. → ficha: — · promovido_para: —
- [LM-013] ajudou=0 mordeu=0 · conf=2026-11-10 · sup: `edição por script` `testes removidos` `corte por âncora` :: Editar um arquivo de teste cortando "do teste A até o teste B" por âncora apaga os testes que estavam no meio sem nenhum erro: na F19 três testes sumiram assim, a suíte continuou verde, e o ledger da revisão seguiu citando dois deles como prova. **Do instead:** depois de uma edição por corte, compare a lista de testes de antes e de depois (`grep -c "def test_"`), e trate teste citado em ledger ou relatório como contrato: se o nome some, o registro mente. → ficha: — · promovido_para: —
